# 대사·용어 편집기 — kernel 초과 462건

## 목표

`kernel.bin` 텍스트 462건이 원래 자리보다 길어 못 들어간다. 사람이 직접 줄이면서
실시간으로 확인할 수 있게 편집기를 넓힌다. 필드 대사 편집 기능은 그대로 둔다.

## 실측 (2026-08-08)

| 항목 | 값 |
|---|---|
| 초과 | 462건 / 합계 1,248B (중앙값 2B, 최대 17B) |
| 초과 1~2B | 300건 · ≤4B 387건 |
| 음절 교체만으로 해결 가능(이론) | 337건 |
| `이름 :: 설명` 오염 | 105건 (그중 초과 52건) |
| 뱅크1(≥882) 음절을 쓰는 문장 | 194건 (그중 자리도 넘침 83건) |
| 제어 토큰이 있는 원문 | 12건 — 번역이 전부 지키고 있다 |

핵심: 초과의 원인은 문장 길이보다 **음절 값**이다. 배치의
`single_byte_limit = 224` — 인덱스 224 미만은 1바이트, 그 위는 2바이트다.
`헤이스트`가 5B 인 것은 `헤`(580)가 2바이트 구간이기 때문이다.

## 자료 형태 — `work/text/kernel-text-ko.json` 의 한 행

**로컬에 그대로 둔다** (사용자 결정). git 밖이라 저장할 때마다 `.bak` 을 남긴다.

```jsonc
{
  "offset": 19981,          // 기존 — 제자리 삽입 좌표
  "section": 31,            // 새로 — 섹션 번호 (집계·필터)
  "ja": "装備している武器で攻撃します",   // 기존 — ① 일본어 원문 (제어 토큰 인라인)
  "raw_hex": "19cc1a3b…",   // 기존 — ④ 원문 글리프 코드
  "source": "qwen-desc",    // 기존 — 초벌 출처
  "ko_draft": "무장한 무기로 공격합니다",  // 새로 — ② 초벌 (동결. 기계가 여기만 쓴다)
  "ko_short": null,         // 새로 — ③ 축약문 (사람). null = 아직 안 봄
  "ko": "무장한 무기로 공격합니다",        // 기존 이름 유지 — **화면에 나가는 글자**
  "ko_hex": "5da66e5f…",    // 새로 — ④ ko 의 글리프 코드
  "slot_bytes": 20,         // 새로 — ⑤ 안전 슬롯 (원본 NUL 까지의 칸)
  "used_bytes": 15,         // 새로 — 지금 쓰는 바이트
  "note": ""                // 새로 — 사람 메모
}
```

**불변식:** `ko == (ko_short if ko_short is not None else ko_draft)`.

`ko` 를 계약 칸으로 남겨 두는 이유 — 이 칸을 읽는 소비자가 다섯이다
(불변식 25: 소비자를 전부 센다).

| 소비자 | 무엇을 거는가 | 이 설계에서 |
|---|---|---|
| `insert_kernel_text.py` | 디스크에 쓸 글자 | 그대로 — 자동으로 축약문을 읽는다 |
| `build_layout_all.py --also` | 화면에 나갈 음절 전부 | 그대로 |
| `verify_layout.py` | 같은 음절 집합 (뱅크0 관문) | 그대로 |
| `tower.py` | 링크·미반영 집계 | 그대로 |
| `translate_kernel_desc_local.py` | 빈 초벌을 채운다 | **가드 필요** — 사람 축약문을 덮으면 안 된다 (불변식 26) |

## 작업 노트

- `raw_hex` 길이 == 삽입기가 재는 `room`(NUL 까지)이 1,320건 전부 일치. 편집기는
  원본 BIN 없이도 정확한 예산을 안다
- `ja == decode(raw_hex)` 도 1,320건 전부 일치, 왕복 무손실
- 뱅크1 음절은 `korean_map()` 의 `glyphs.index` 가 아니라 `bank1.index` 에 있다.
  둘 다 봐야 194건이 보인다 (한쪽만 보면 0건으로 나온다)
- pytest 없음. 검증은 스크립트 안 `--check` 로 붙인다
