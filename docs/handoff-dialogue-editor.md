## 배경 — 왜 이 작업이 필요한가

`kernel.bin`(IMG TOC#129, LBA 831, 35,976B)에는 화면에 나가는 텍스트가
범주별 섹션으로 들어 있다.

```
#31 전투 커맨드   #32 마법      #34 어빌리티   #35 무기
#37 캐릭터 이름   #38 아이템    #39 아이템 설명 #55 전투 결과
```

번역은 1,320건 전부 끝났다(`work/text/kernel-text-ko.json`). 그중 **858건은
들어갔고 462건은 원래 자리보다 길어 못 들어갔다.**

```
#39 아이템 설명  141건    #32 마법      59건    #34 어빌리티  52건
#55 전투 결과     36건    #31 전투커맨드 31건    #33          19건
#42 17건  #46 13건  #38·#47 12건  #44 11건  #35 9건  #45 7건  … 그 밖
```

### 왜 자리를 못 넘기는가

문자열마다 **원래 자리와 원래 NUL 위치를 그대로 둬야 한다.**

- 구조체 섹션이 문자열을 **절대 오프셋으로 가리킨다**(파일 앞부분에 그런 u32 가
  234개). 짧아진 만큼 당겨 쓰면 전부 어긋난다 — 실제로 캐릭터 이름이 통째로
  공백이 됐다
- 남는 자리는 **공백 `0x5f`** 로 메운다. NUL 로 메우면 널 개수가 늘어 문자열을
  널로 세는 코드가 어긋난다

검산 불변식은 하나다 — **NUL 위치가 원본과 완전히 같은가.**
자세한 사연은 `docs/lessons.md` 18번.

### 편집기가 보여 줘야 할 것

지금 `dialogue_editor.py` 가 필드 대사에 대해 보여 주는 세 가지와 성격이 같다.

```
바이트 예산   원본 길이. 넘으면 in-place 교체가 깨진다
줄 픽셀 폭    원본 실측 최대 302px
줄 수         원본 줄 수
```

kernel 은 **바이트 예산 하나가 거의 전부**다(창이 아니라 슬롯 제약이라).
「이 문장은 자리가 22B 인데 지금 31B 다, 9B 줄여야 한다」를 실시간으로.

### 자료에 이미 있는 흠

- **105건이 `이름 :: 설명` 형식**으로 왔다. 원본은 설명만이라 그대로 쓰면 크게
  넘친다. `insert_kernel_text.strip_name()` 이 걷어내지만, **번역 자료 자체를
  고치는 편이 낫다** — 편집기에서 보이면 그때 정리한다
- 용어 일관성(드로우·버서크 등)은 Notion 공략집을 정본으로 맞춰 왔다

## 별개로 남아 있는 것 (편집기 작업과 섞지 않는다)

- **kernel 음절 104자가 뱅크1**(게임 인덱스 ≥882)에 있어 화면에서 깨진다
  (`닉` — 피닉스의 꼬리). 메뉴를 그리는 오버레이가 뱅크 비트를 안 더한다.
  `verify_layout.py` 가 매번 잡아 준다. 고치려면 **배치 생성기가 kernel 음절도
  뱅크0 에 우선 배치**해야 한다 — 메뉴에 이미 하는 처리와 같다
- 이름 뒤 반자 공백(`0x5f` 패딩). 조기 NUL 로 없앨 수 있으나 NUL 이 늘어
  위험하다. 가르는 실험이 필요하다
- 튜토리얼 삽입 도구 없음
- 전투 이름 글꼴의 원본 아카이브 미확정 (`docs/roadmap.md` 항목 6)

## 실행

```bash
./대사편집기.command                     # Finder 에서 두 번 눌러도 된다
python3 scripts/insert_kernel_text.py --dry-run   # 무엇이 얼마나 넘치는지
python3 scripts/tower.py --status                 # 전체 상태·링크·미반영
```
