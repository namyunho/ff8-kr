## 1회차에서 한 것 (2026-08-08)

**자료 형태.** `work/text/kernel-text-ko.json` 한 행이 다섯을 나란히 담는다 —
일본어 원문(`ja`)·원문 글리프 코드(`raw_hex`)·한국어 초벌(`ko_draft`)·
한국어 축약문(`ko_short`)·안전 슬롯(`slot_bytes`). 우선순위는 하나다:
**축약이 있으면 축약, 없으면 초벌**이 `ko` 로 나간다.

`ko` 라는 칸 이름을 그대로 둔 것이 핵심이다. 이 칸을 읽는 소비자가 다섯인데
(삽입기·`build_layout_all`·`verify_layout`·관제탑·기계번역기) 이름을 바꾸면
**셋은 고쳐도 조용히 틀린다.** 그래서 삽입기는 한 줄도 안 고쳤다.

**새 도구.**

```
scripts/text_measure.py      글자마다의 바이트 비용. 세지 않고 인코더를 부른다
scripts/text_rows.py         스키마 정본·우선순위·원자적 저장(.bak + 날짜 사본)
scripts/migrate_kernel_rows.py  일회성 이관 (멱등). 삽입 바이트 불변을 검산한다
scripts/text_editor.py       kernel 편집 화면 (Tkinter)
data/location-names.json     지명 19개 — 코드에서 뺐다
```

**편집기가 색으로 알려 주는 것.** 노랑 = 2바이트 음절(줄일 여지),
빨강 = 뱅크1(화면에서 깨진다), 자주 = 배치에 없음, 파랑 = 제어 토큰.

**왜 색이 중요한가.** 초과의 원인은 문장 길이보다 **음절 값**이다.
배치의 `single_byte_limit` 이 224라 인덱스 224 미만은 1바이트, 그 위는
2바이트다. `헤이스트`가 5B 인 것은 `헤`(580)가 2바이트 구간이라서다.
**초과분보다 2바이트 음절이 많은 줄이 대부분이다** — 문장을 줄이기
전에 싼 동의어로 바꾸는 쪽이 먼저다.

**함께 정리한 것.** `이름 :: 설명` 105건을 이관에서 걷어냈다(떼어낸 접두는
`note` 에 남겼다). 삽입기가 어차피 `strip_name()` 으로 걷어내므로, 안
걷어내면 편집기가 보여 주는 초과 바이트가 실제와 달랐다.

**남은 것.** 초과 0건. 축약도 67건만 남았다(전 396건) — 전부 설명문이고 **아이템·마법·어빌리티 이름은 완역 그대로**다. 메뉴·이름·필드
어댑터는 아직 안 붙였다(필드는 기존 `dialogue_editor.py` 그대로).


## 배경 — 왜 이 작업이 필요한가

`kernel.bin`(IMG TOC#129, LBA 831, 35,976B)에는 화면에 나가는 텍스트가
범주별 섹션으로 들어 있다.

```
#31 전투 커맨드   #32 마법      #34 어빌리티   #35 무기
#37 캐릭터 이름   #38 아이템    #39 아이템 설명 #55 전투 결과
```

번역은 1,320건 전부 끝났고 **전부 들어간다** — `insert_kernel_text.py --repack all`
이 글자 섹션을 다시 짜면서 **오프셋 표까지 함께 고치기** 때문이다.

```
#32 마법 9건   #34 어빌리티 7건   #35 무기 2건   #55 전투결과 2건
#33·#49·#51 각 1건
```

남은 23건은 **전부 음역된 고유명사**다(블리자드·헤이스트·메테오·아포칼립스
따위). 1~3바이트가 모자라는데 **글자로는 더 못 줄인다** — 가나 한 글자가
1바이트인 자리에 한글 음절을 넣는 것이라, 음절이 전부 1바이트 구간에
있어야만 들어간다. 그리고 **1바이트 구간 224칸은 포화다**(아래).

숫자는 배치를 고칠 때마다 달라진다. **적힌 값을 믿지 말고 다시 잰다.**

```bash
python3 scripts/text_editor.py --check
```

### 왜 자리를 못 넘기는가

문자열마다 **원래 자리와 원래 NUL 위치를 그대로 둬야 한다.**

- 구조체 섹션이 문자열을 **절대 오프셋으로 가리킨다**(파일 앞부분에 그런 u32 가
  234개). 짧아진 만큼 당겨 쓰면 전부 어긋난다 — 실제로 캐릭터 이름이 통째로
  공백이 됐다
- 남는 자리는 **공백 `0x5f`** 로 메운다. NUL 로 메우면 널 개수가 늘어 문자열을
  널로 세는 코드가 어긋난다

검산 불변식은 하나다 — **NUL 위치가 원본과 완전히 같은가.**
자세한 사연은 `docs/lessons.md` 18번.

### 편집기가 보여 줘야 할 것

지금 `dialogue_editor.py` 가 필드 대사에 대해 보여 주는 세 가지와 성격이 같다.

```
바이트 예산   원본 길이. 넘으면 in-place 교체가 깨진다
줄 픽셀 폭    원본 실측 최대 302px
줄 수         원본 줄 수
```

kernel 은 **바이트 예산 하나가 거의 전부**다(창이 아니라 슬롯 제약이라).
「이 문장은 자리가 22B 인데 지금 31B 다, 9B 줄여야 한다」를 실시간으로.

### 자료에 이미 있는 흠

- **105건이 `이름 :: 설명` 형식**으로 왔다. 원본은 설명만이라 그대로 쓰면 크게
  넘친다. `insert_kernel_text.strip_name()` 이 걷어내지만, **번역 자료 자체를
  고치는 편이 낫다** — 편집기에서 보이면 그때 정리한다
- 용어 일관성(드로우·버서크 등)은 Notion 공략집을 정본으로 맞춰 왔다

## 별개로 남아 있는 것 (편집기 작업과 섞지 않는다)

- ~~kernel 음절 104자가 뱅크1~~ **끝났다(배치 v14~v17).** 생성기가 kernel
  음절도 뱅크0 에 우선 배치한다. `닉`(피닉스의 꼬리)이 정상으로 나온다
- **1바이트 구간 224칸이 포화다.** 남은 23건을 고치려고 음절을 더 올리면
  빈도 213~248 짜리가 밀려나 **초과가 도리어 는다**(23 -> 30줄). `메` 하나를
  올려 본 실측이다. 늘리려면 224 라는 값 자체를 바꿔야 하는데 그것은 게임의
  텍스트 해독기가 정하는 값이다
- 이름 뒤 반자 공백(`0x5f` 패딩). 조기 NUL 로 없앨 수 있으나 NUL 이 늘어
  위험하다. 가르는 실험이 필요하다
- 튜토리얼 삽입 도구 없음
- 전투 이름 글꼴의 원본 아카이브 미확정 (`docs/roadmap.md` 항목 6)
