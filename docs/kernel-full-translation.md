# kernel.bin 을 축약 없이 완역할 수 있는가 (2026-08-09)

> **2026-08-09 정정.** 처음에 「게임이 널을 세어 문자열을 찾으므로 자리를
> 옮겨도 된다」고 적었다. **틀렸다.** 실기에서 문자열이 통째로 밀렸고
> 키스티스 이름이 안 떴다. 문자열은 **u16 상대 오프셋 표**로 가리켜진다.
> 아래는 정정한 내용이다. 틀린 판단의 경위는 `lessons.md` 21번.

## 결론

**축약은 기술적 필연이 아니다. 다만 값이 비싸다** — 문자열을 옮기려면
**오프셋 표 25벌을 빠짐없이 찾아 다시 써야** 하고, 지금 **21벌**을 찾았다.

## 무엇이 사실인가

### 1. 완역은 279바이트가 모자랄 뿐이다

```
문자열 풀 합계   16,000B
완역 필요 합계   16,279B      -279B  (1.7%)
```

### 2. 279바이트를 놓을 자리가 이미 있다

```
kernel.bin  LBA 831  35,976B  →  18섹터 = 36,864B
마지막 섹터의 남는 자리 888B   (전부 0x00)
```

### 3. 문자열은 **u16 상대 오프셋**으로 가리켜진다  ← 여기가 틀렸던 곳

글자 섹션마다 **짝이 되는 구조체 섹션**이 있고, 그 안의 레코드가
`u16 이름오프셋 / u16 설명오프셋`을 갖는다. 값은 **글자 섹션 시작 기준
상대 오프셋**이다.

    #39 아이템 설명 332개  ←  #8 이 332칸짜리 u16 통짜 표
    #55 전투 결과  128개  ←  #30 이 128칸짜리 u16 통짜 표
    #47 어빌리티            ←  #17 이 8B 레코드 24개, 필드 +0(이름) +2(설명)

**내가 이것을 못 본 이유는 상대 오프셋을 한 번도 안 재 봤기 때문이다.**
절대 오프셋(u32·u16)만 훑고 「33개뿐」이라는 숫자를 얻어, 「나머지 1,287개는
널을 세어 찾는 모양」이라고 **없는 것을 근거로 결론지었다.**

「글자 섹션이 널로 이어 붙인 순열이다」는 참이지만, 그것은 **문자열을 세어
찾는다는 증거가 아니다** — 그냥 문자열이 이어져 있다는 뜻일 뿐이다.

## 완역으로 가는 길 (수정)

1. **오프셋 표 25벌을 전부 찾는다.** 21벌 찾았다. 남은 4벌이 관문이다
2. 글자 섹션을 다시 짜고 **표를 새 오프셋으로 다시 쓴다**
3. 섹션이 자란 만큼 뒤를 밀고, 머리의 56칸 섹션 오프셋 표를 고친다
4. 파일을 279B 늘린다 (섹터 여유 888B 안). IMG TOC 크기를 올린다
5. 게임이 크기를 TOC 에서 읽는지 확인한다

## 실기에 올리기 전에 반드시 할 검산

이번에 이것을 안 해서 사용자가 깨진 판을 돌렸다.

- **항등 검산.** 표를 다시 쓰는 코드로 **자리를 하나도 안 옮기고** 돌려서
  파일이 **바이트 단위로 원본과 같은지** 본다. 여기서 어긋나면 표 이해가
  틀린 것이다 — 게임을 켜기 전에 잡힌다
- **뒤섞기 검산.** 문자열 순서를 그대로 두고 길이만 1바이트씩 늘려 본 뒤,
  모든 표의 값이 **정확히 그만큼** 움직였는지 되읽어 확인한다
- **가리켜지지 않는 문자열이 0개인가.** 표 25벌이 문자열 1,320개를 빠짐없이
  덮어야 한다. 하나라도 남으면 그것이 다음 「키스티스 이름」이다
