# kernel.bin 을 축약 없이 완역할 수 있는가 — 실측 (2026-08-09)

**결론: 축약은 기술적 필연이 아니다.** 지금 축약하는 이유는 삽입기가
**「문자열을 절대 옮기지 않는다」**는 정책을 쓰기 때문이고, 그 정책은 게임의
성질이 아니라 우리가 안전을 위해 고른 것이다.

## 재 본 것

### 1. 완역은 279바이트가 모자랄 뿐이다

문자열 풀 전체와, 축약하지 않은 초벌(`ko_draft`) 전체를 인코더로 재 봤다.

```
문자열 풀 합계   16,000B
완역 필요 합계   16,279B      -279B  (1.7%)
```

섹션 25개 중 13개가 넘치고 12개가 남는다. 남는 쪽 합이 340B, 넘치는 쪽 합이
619B다. **섹션 경계를 넘어 옮길 수 있으면 279B만 있으면 된다.**

### 2. 279바이트를 놓을 자리가 이미 있다

```
kernel.bin  LBA 831  35,976B  →  18섹터 = 36,864B
마지막 섹터의 남는 자리 888B   (전부 0x00)
다음 항목 TOC#130 은 LBA 849 — 우리 마지막 섹터 바로 다음
```

**888B 가 kernel.bin 자기 섹터 안에서 놀고 있다.** 279B를 쓰는 데 디스크의
다른 파일을 하나도 안 밀어도 된다.

### 3. 문자열은 널을 세어 찾는다 — 그래서 자랄 수 있다

글자를 담은 섹션 25개가 **예외 없이** 「섹션 시작부터 널로 이어 붙인 순열」
이었다. 번역 자료가 아는 문자열 1,320개의 자리가 그 순열과 정확히 일치한다.

즉 게임은 **N번째 문자열을 널을 N번 세어** 찾는다. 그러면 지켜야 할 것은
**개수와 차례**지 절대 위치가 아니다. **길이는 마음대로 바꿔도 된다.**

    지금 지키는 것   문자열마다 원래 자리 + 원래 NUL 위치   <- 필요 이상으로 세다
    실제로 지킬 것   섹션의 널 개수와 차례                  <- 이것만

이것이 예전에 겪은 두 가지 사고와 앞뒤가 맞는다(`lessons.md` 18번).

- 섹션을 다시 짜서 **당겨** 썼더니 캐릭터 이름이 공백이 됐다 → 절대 참조가
  있는 소수의 문자열이 어긋났다
- 남는 자리를 **NUL 로** 메웠더니 어긋났다 → 널 개수가 늘어 세기가 밀렸다

### 4. 절대 참조는 33개뿐이다

구조체 섹션(글자 없는 섹션) 안에서 문자열 자리를 그대로 가리키는 값은
142자리 · 문자열 33개다. 그중 상당수는 우연히 값이 겹친 것일 수 있으니
**실제 참조를 가리는 검산이 따로 필요하다.** 어느 쪽이든 **1,320개가 아니라
수십 개**를 다루는 문제다.

## 완역으로 가는 길

1. 텍스트 섹션을 **새로 짠다** — 완역을 널로 이어 붙인다. 개수·차례를 보존
2. 섹션이 자란 만큼 **뒤 섹션을 민다**. 머리의 56칸 오프셋 표를 다시 쓴다
3. 절대 참조 33개를 새 자리로 옮긴다
4. 파일이 36,255B 가 된다 → **IMG TOC 의 크기 항목을 올린다** (888B 여유 안)
5. 검산: 섹션마다 **널 개수가 원본과 같은가**, 되읽기 일치, 실기에서 확인

## 남은 위험 두 가지 (실기로 갈라야 한다)

- **게임이 kernel.bin 크기를 TOC 에서 읽는가, 고정 버퍼에 담는가.**
  고정이면 36,255B 를 못 쓴다. 이때는 279B 를 섹션 재배치만으로 흡수해야
  하는데, 남는 쪽 340B 가 넘치는 쪽 619B 를 다 못 덮으므로 **일부는 여전히
  축약해야 한다**(다만 지금 23건이 아니라 훨씬 적어진다)
- **절대 참조 33개가 진짜인가.** 하나라도 놓치면 그 항목의 이름이 공백이
  된다 — 예전에 겪은 그 증상이다. 다행히 증상이 눈에 확 띈다

## 지금 상태와 되돌리기

축약은 **덧씌운 것**이라 완역이 손상되지 않았다.

```
work/text/kernel-text-ko.json   1,320행 전부 ko_draft(완역)가 살아 있다
                                396행에 ko_short 가 얹혀 있다
ko_short 를 비우면 곧바로 완역으로 돌아간다 (text_rows.effective 의 우선순위)
```

분기 `before-kernel-shorten`(099fca0)이 축약 직전 상태다.

## 다른 자료는 어떤가

- **필드 대사** — 이미 자란다. `patch_disc` 가 원본 크기를 못 지키면 섹션을
  민다(지금 62개 필드가 그렇다). 여기는 애초에 막힌 곳이 아니다
- **메뉴** — `insert_menu_text.STRICT_GROUPS`(그룹 7·8)만 제자리 제약이다.
  이름 입력 글자판의 **한 줄 5바이트 고정**은 게임이 바이트로 세는 것이라
  진짜 제약이다
- **1바이트 구간 224칸** — 이것은 게임의 텍스트 해독기가 정하는 값이라
  **못 늘린다.** 다만 kernel 을 자라게 하면 이 제약은 「자리에 못 들어감」이
  아니라 「본문이 조금 커짐」으로 성격이 바뀐다
